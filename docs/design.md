# 설계서: 학교 일정 공유 바탕화면 위젯 (1차)

작성일: 2026-11-03 · 근거 자료: [research.md](research.md)

## 1. 목표

선생님들이 학교 Google 계정으로 로그인해 일정을 등록하면, 모든 선생님 PC의 바탕화면 위젯에 **즉시** 표시된다. 위젯은 **항상 바탕화면에 있고, 멈추거나 다른 프로그램과 부딪히지 않아야** 한다. 선생님 본인 수업 시간표도 함께 보여 준다.

### 1차 범위

| 포함 | 제외 (2차 이후) |
|---|---|
| 바탕화면 상주 위젯, 트레이, 자동 시작, 자동 업데이트 | 버튼 독 (소프트웨어 Stream Deck) |
| 일정 보기 (월/주/일/목록), 등록·수정·삭제, 반복, 실시간 반영, 알림 | 반·부서별 달력 |
| Google 학교 계정 로그인 (`@chunchon.gwe.hs.kr`만 허용) | 웹/모바일 등록 페이지 |
| 본인 수업 시간표 **직접 입력** + 현재 교시 강조 | 시간표 자동 연동 (방법이 생기면 교체, §5.4) |
| | 외부 달력 연동 (구글 캘린더 등) |
| 테마·투명도·영역 켜기/끄기 | |

## 2. 전체 구조

```
 선생님 PC (여러 대)                          학교 서버 PC (1대, 상시 켜짐)
┌───────────────────────────┐               ┌────────────────────────────────┐
│ 위젯 앱 (Tauri)            │   HTTPS/SSE   │ PocketBase                     │
│ ├ 화면: React + Schedule-X │ ◀───────────▶ │ ├ DB (SQLite): users, events,  │
│ ├ 로컬 캐시 (오프라인)       │               │ │   timetable_slots, bell_times │
│ ├ 알림 예약                 │               │ ├ 실시간 구독 (SSE)             │
│ └ Rust: 창 고정·트레이·감시  │               │ ├ Google OAuth2 + 도메인 검사   │
└───────────────────────────┘               │ ├ 자동 백업                     │
          │                                 │ └ 업데이트 파일 배포 (pb_public) │
          │ Google 로그인 (브라우저)          └────────────────────────────────┘
          ▼
   accounts.google.com
```

- 위젯은 **서버 하나만** 바라본다. 시간표도 서버에 저장하므로 선생님이 PC를 바꿔도 그대로 보인다.
- 서버가 꺼져도 위젯은 마지막으로 받은 일정·시간표를 계속 보여 준다.

## 3. 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 위젯 앱 | **Tauri 2** | 설치파일 수 MB, 메모리 적음, Windows WebView2 사용. 공식 플러그인으로 자동 시작·단일 인스턴스·업데이트·알림·창 상태 저장 해결 |
| 화면 | **React + TypeScript + Vite** | 자료·예제가 가장 많음. 디자인을 CSS로 따로 입히기 쉬움 |
| 달력 | **Schedule-X** (MIT) | 가볍고 테마 커스터마이즈 쉬움, 반복 일정 플러그인 있음 |
| 서버 | **PocketBase** (MIT) | 실행파일 1개에 DB·API·실시간·OAuth2·관리자 화면·백업 포함 |
| 반복 일정 계산 | RRULE 문자열 + rrule.js | 표준 형식, 나중에 .ics 내보내기에도 그대로 사용 |

## 4. 위젯 앱 상세

### 4.1 바탕화면 상주 (가장 중요)

| 요구 | 구현 |
|---|---|
| 항상 바탕화면에 보임 | 창을 **바탕화면 계층(WorkerW/Progman)의 자식**으로 붙임. 단순 "항상 아래" 창은 `Win+D`(바탕화면 보기)를 누르면 사라지기 때문. Rainmeter·Lively가 쓰는 방식 |
| 다른 창을 가리지 않음 | 기본은 바탕화면 고정. 트레이 메뉴에서 "잠시 위로 띄우기" 전환 |
| 테두리·작업표시줄 없음 | `decorations: false`, `skipTaskbar: true`, 투명 배경 |
| 위치·크기 기억 | `tauri-plugin-window-state`. 모니터가 빠져서 화면 밖이면 주 모니터로 되돌림 |
| 클릭 통과 잠금 | 트레이 메뉴 "위치 잠금" → `set_ignore_cursor_events` |
| 탐색기 재시작 대응 | 탐색기가 재시작되면 바탕화면 계층이 새로 만들어짐 → `TaskbarCreated` 메시지를 받으면 다시 붙임 |

### 4.2 안정성 ("충돌이 적어야")

| 위험 | 대책 |
|---|---|
| 앱을 두 번 실행 | `tauri-plugin-single-instance`: 두 번째 실행은 기존 창을 앞으로 가져오고 종료 |
| 화면(WebView2) 프로세스 다운 | WebView2 `ProcessFailed` 이벤트 감지 → 화면만 다시 로드 |
| 앱 전체 다운 | Rust 패닉 시 로그 기록 후 종료 코드 반환 → 작업 스케줄러 "실패 시 재시작" 설정으로 1분 내 재실행 |
| 게임·전체화면 발표 중 방해 | Windows `SHQueryUserNotificationState`로 전체화면·발표 모드 감지 → 화면 갱신 중지, 알림은 모아 두었다가 끝난 뒤 표시 |
| 장시간 실행 시 메모리 증가 | 하루 1회(새벽) 또는 메모리 임계치 초과 시 화면만 조용히 다시 로드 |
| 네트워크 끊김 | 실시간 연결 끊기면 지수 백오프로 재연결, 그동안 캐시 표시 + "오프라인" 표시 |
| 원인 파악 | `tauri-plugin-log`로 `%APPDATA%\dashboards_school\logs`에 일자별 로그, 7일 보관 |

### 4.3 자동 시작·업데이트

- `tauri-plugin-autostart`: Windows 로그인 시 실행 (설정에서 끌 수 있음)
- `tauri-plugin-updater`: 시작 시·하루 1회 서버의 `pb_public/updates/latest.json` 확인 → 서명 검증 후 설치. 업데이트 파일을 학교 서버가 직접 배포하므로 외부 호스팅 불필요

### 4.4 화면 구성

```
┌──────────────────────────────┐
│ 11월 3일 (월)   3교시 수학 ●  │ ← 오늘 + 현재 교시
├──────────────────────────────┤
│ [월] [주] [일] [목록]    ＋    │
│                              │
│        달력 (Schedule-X)      │
│                              │
├──────────────────────────────┤
│ 오늘 수업: 1 2-3 수학 3 1-5 … │ ← 켜기/끄기 가능
└──────────────────────────────┘
```

- 일정 클릭 → 상세 / 본인 일정이면 수정·삭제
- `＋` 또는 날짜 더블클릭 → 등록 창 (별도 작은 창)
- 시간표 편집 창: 요일×교시 표에서 칸을 눌러 과목·반·교실 입력, 칸 복사/비우기
- 설정 창: 로그인 계정, 테마, 투명도, 영역 켜기/끄기, 자동 시작, 알림 시간
- **디자인은 별도 작업**: 색·글꼴·간격은 CSS 변수(디자인 토큰)로만 정의해 나중에 통째로 교체할 수 있게 함

### 4.5 로컬 저장

| 내용 | 위치 |
|---|---|
| 일정·시간표 캐시 | `tauri-plugin-store` (JSON) — 앞뒤 3개월 범위만 |
| 로그인 토큰 | Windows 자격 증명 관리자 (`keyring` crate) — 평문 파일에 두지 않음 |
| 위젯 설정 | `tauri-plugin-store` |

### 4.6 알림

- 캐시된 일정 기준으로 시작 N분 전(기본 10분, 설정 가능) Windows 토스트 (`tauri-plugin-notification`)
- 일정이 바뀌면 예약을 다시 계산. 전체화면 중이면 보류 후 표시

## 5. 서버 상세 (PocketBase)

### 5.1 데이터 모델

**users** (인증 컬렉션)

| 필드 | 형식 | 비고 |
|---|---|---|
| email | email | Google 계정, `@chunchon.gwe.hs.kr`만 |
| name | text | Google 프로필 이름 |
| role | select: `member`, `admin` | 기본 `member` |

**events**

| 필드 | 형식 | 비고 |
|---|---|---|
| title | text, 필수, 최대 100자 | |
| description | text, 최대 2000자 | |
| location | text | |
| start / end | date | 종일 일정은 날짜만 사용 |
| all_day | bool | |
| category | select: 학사, 회의, 행사, 출장, 기타 | 색상은 화면에서 분류별로 지정 |
| rrule | text | 반복 규칙 (예: `FREQ=WEEKLY;BYDAY=MO`), 비어 있으면 1회 |
| exdates | json | 반복 중 빠지는 날짜 |
| owner | relation → users | 서버가 자동 설정 |
| created / updated | autodate | |

**timetable_slots** (선생님 본인 수업, 직접 입력)

| 필드 | 형식 | 비고 |
|---|---|---|
| owner | relation → users | 서버가 자동 설정 |
| weekday | number 1~5 | 월~금 |
| period | number 1~9 | 교시 |
| subject | text | 과목명 |
| class_label | text | 예: `2-3` |
| room | text | 선택 |
| term | text | 예: `2026-2` (학기별로 따로 저장, 새 학기에 복사 가능) |

**bell_times** (교시 시작·종료 시각, 학교 공통)

| 필드 | 비고 |
|---|---|
| period | 교시 |
| start / end | `HH:MM` |

### 5.2 접근 규칙

| 컬렉션 | 조회 | 생성 | 수정·삭제 |
|---|---|---|---|
| events | 로그인한 사용자 | 로그인한 사용자 (`owner`는 본인으로 강제) | 작성자 본인 또는 `admin` |
| timetable_slots | 본인 것만 | 본인 (`owner` 강제) | 본인 |
| bell_times | 로그인한 사용자 | `admin` | `admin` |
| users | 본인 + 다른 사용자 이름만 | OAuth 로그인 시 자동 | 본인(이름만), `role`은 `admin`만 |

### 5.3 로그인 흐름 (Google)

1. 위젯이 기본 브라우저로 Google 로그인 페이지를 연다 (`hd=chunchon.gwe.hs.kr` 지정, PKCE 사용)
2. 로그인 후 Google이 `http://127.0.0.1:<임시포트>`로 돌려보냄 → 위젯이 받은 code를 PocketBase에 전달 (`authWithOAuth2Code`)
3. PocketBase가 Google과 토큰 교환 → **서버 훅이 이메일 도메인 재확인** (`hd` 파라미터는 화면 힌트일 뿐이라 서버 검사가 필수). 아니면 거부
4. 위젯은 PocketBase 토큰을 자격 증명 관리자에 저장, 만료 전 자동 갱신

Google Cloud 쪽 준비: OAuth 클라이언트 유형 **"데스크톱 앱"** 1개, 동의 화면 **"내부"**(학교 조직 사용자만) — 학교 Workspace 관리자 권한 또는 승인 필요.

### 5.4 시간표

**1차: 직접 입력.** 선생님이 본인 수업을 `timetable_slots`에 입력하고, `bell_times`와 합쳐 현재·다음 교시를 계산한다. 시험·행사로 시간표가 바뀌는 날은 일정(events)으로 등록해 함께 보여 준다.

**나중에 자동 연동으로 교체할 수 있게:** 화면은 "이번 주 수업 목록(요일, 교시, 과목, 반, 교실)"만 받도록 만들고, 그 목록을 만드는 부분을 분리해 둔다. 자동으로 가져올 방법이 생기면 그 부분만 바꾼다.

조사해 둔 후보:
- 나이스 `hisTimetable` API: 반 단위 시간표만 제공 → 교사별로 쓰려면 "반 시간표에서 내 과목 찾기"가 필요하고, 같은 과목을 여러 교사가 가르치면 구분 불가
- 학교에서 쓰는 시간표 프로그램의 내보내기 파일(엑셀 등) 가져오기 — 학교 확인 필요

### 5.5 운영

| 항목 | 방법 |
|---|---|
| 상시 실행 | PocketBase를 Windows 서비스로 등록 (NSSM 또는 작업 스케줄러) |
| 주소 | 서버 PC에 고정 IP 할당, 위젯 설정에 서버 주소 입력 (설치 시 기본값 내장) |
| HTTPS | 내부망이라도 로그인 토큰이 오가므로 HTTPS 사용. Caddy 내부 인증서 또는 학교 도메인 하위 주소 + 인증서 중 택1 |
| 백업 | PocketBase 내장 백업을 매일 새벽 실행, 최근 14개 보관 + 주 1회 다른 저장소로 복사 |
| 관리 | PocketBase 관리자 화면(`/_/`)에서 사용자 역할·일정 관리 |

```
dashboards_school/
├─ desktop/                  # 위젯 앱
│  ├─ src/                   # React 화면

│  ├─ pb_hooks/              # 도메인 검사, owner 강제
│  └─ pb_public/updates/     # 위젯 업데이트 파일
├─ docs/
└─ .claude/                  # 스킬 (impeccable, taste-skill)
```

PocketBase 실행파일·`pb_data`(DB)는 git에 올리지 않는다.

|---|---|---|

| M7 | 디자인 적용·서버 PC 배포·선생님 몇 명 시범 사용 | 시범 사용자 1주일 사용 중 문제 없음 |

## 8. 열린 문제

1. **시간표 자동 연동** (보류): 1차는 직접 입력으로 결정(2026-11-03). 교사별 시간표를 자동으로 가져올 방법이 확인되면 §5.4 구조대로 교체
2. **Google Workspace 관리자 승인**: 동의 화면 "내부" 설정과 앱 허용 여부를 학교 관리자에게 확인
